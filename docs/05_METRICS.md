# 试玩指标模板

> 本模板的指标用于本地试玩与质量判断，不代表要接入在线埋点。默认通过自动测试、匿名人工记录或仅在本机存在的调试信息收集；不得上传玩家数据。

## 目的

把“好不好”“看不看得懂”转成定义一致、可计算、能触发决策的证据。指标应直接服务试玩假设，同时用护栏指标避免为了提升一个数字而损害稳定性、可理解性或玩家体验。

## 填写说明

1. 每个主要试玩假设选择一个主要指标，最多添加少量诊断和护栏指标。
2. 在看数据前写清名称、事件、公式、单位、样本、排除条件和阈值。
3. 优先记录行为；主观评分只能作为补充，不能替代观察。
4. 小样本报告原始人数（例如 `3/5`）和中位数，不用虚假的高精度百分比。
5. 每次记录构建版本、配置和固定种子，避免把不同版本混在一起。
6. 指标采集默认手工或本地完成，不安装第三方分析 SDK，不接后端，不使用账号标识。
7. 若某指标必须联网或保存个人数据，先停止并完成新的安全、隐私和范围决策；当前模板不授权该实现。
8. 指标达到阈值只说明假设获得支持，不等于功能已经完成；仍需自动测试和质量检查。

## 推荐问题

- 哪一个数字或行为最能改变本轮的产品决定？
- 指标能否由两个人按同一规则得到相同结果？
- 分母是谁，什么场次必须排除，退出如何计算？
- 指标改善是否可能来自主持人提示、学习效应或种子更简单？
- 需要按新手/熟悉玩家、设备或输入方式分开看吗？
- 平均值是否掩盖了少数严重失败？中位数和原始分布是否更合适？
- 哪个护栏指标能发现崩溃、误触、无法重启或性能退化？
- 数据量不足时怎样表达“不确定”，何时补测？
- 这些数据能否在不收集身份信息、不联网的条件下获得？
- 达到、未达到或落入灰区时，分别采取什么行动？

### 本地事件草案（仅在确有必要时）

事件只用于统一本地观察字段，不表示授权联网发送。

| 事件名                | 触发时机           | 最小字段                    | 禁止字段                    | 对应指标   |
| --------------------- | ------------------ | --------------------------- | --------------------------- | ---------- |
| `[session_started]`   | `[核心状态创建后]` | `[buildId, configId, seed]` | `[姓名、邮箱、设备唯一 ID]` | `[MET-ID]` |
| `[action_resolved]`   | `[核心动作完成后]` | `[actionType, turn, score]` | `[输入原文、身份信息]`      | `[MET-ID]` |
| `[session_restarted]` | `[重启完成后]`     | `[turn, reason]`            | `[身份信息]`                | `[MET-ID]` |

约束：

- 事件来自 `src/core` 的领域结果或稳定 UI 动作，不由动画帧决定。
- 时间指标使用同一场试玩中的单调计时，仅用于本地记录，不进入核心规则。
- 不使用 `Math.random()` 生成会话标识；匿名参与者编号由试玩表分配。
- 默认不写入长期浏览器存储，不发出网络请求。
- 如不需要事件即可回答问题，删除本节事件并采用人工记录。

## 完成判定标准

- [ ] 每个主要假设只有一个主要指标，并有诊断或护栏补充。
- [ ] 每项指标的起点、终点、分子、分母、公式、单位和排除条件无歧义。
- [ ] 阈值与对应行动在看结果前确定，灰区有补测规则。
- [ ] 记录包含构建、配置、种子和必要分组，结果可以复算。
- [ ] 小样本使用原始人数、中位数和范围，没有伪精确结论。
- [ ] 技术故障、主持人提示和学习效应不会被误算为玩家行为。
- [ ] 默认无联网、账号、第三方分析 SDK、长期标识或个人数据。
- [ ] 自动测试指标和真人试玩指标各自边界清楚。
- [ ] 指标结论能触发明确的保留、调整、移除、补测或停止决定。

# 试玩计划模板

> 试玩不是“问玩家喜不喜欢”，而是用真实行为验证一个明确假设。默认采用本地构建、人工观察和匿名汇总，不接入线上分析服务。

## 目的

规定要验证的试玩假设、参与者、任务、观察方式、判定阈值和结果处理，让不同主持人能够以相近方式执行试玩，并把发现转化为继续、调整或停止的决策。

## 填写说明

1. 每轮试玩优先验证一个主要假设，最多增加两个次要问题。
2. 假设必须描述“哪类玩家在什么条件下会出现什么可观察行为”。
3. 先写通过与失败阈值，再邀请参与者，避免看过结果后改变标准。
4. 试玩版本必须通过自动测试并记录版本、配置、固定种子和设备。
5. 给玩家目标，不提示具体操作；主持人按统一脚本执行并区分观察与解释。
6. 只收集做决策所需的最少信息。默认不记录真实姓名、账号、联系方式、音视频或其他个人数据。
7. 若确需录音、录像或远程数据，必须先取得明确同意并制定保存与删除方式；本模板不提供在线采集。
8. 把事实、玩家原话（少量）和团队推断分开记录。
9. 单次小样本用于发现问题，不用于证明普遍比例；结论必须说明样本限制。

## 推荐问题

- 本轮最重要、最可能改变方向的未知是什么？
- 什么行为能支持假设，什么行为会推翻它？
- 参与者是否接近目标玩家，还是便利样本？
- 主持人的措辞是否泄露了操作方法或期望答案？
- 试玩版本、配置和种子能否在之后完整复现？
- 玩家第一次犹豫、误触或停下发生在哪里？
- 玩家是否理解目标、动作后果、分数和结束原因？
- 重启后，玩家会立刻尝试不同策略还是重复同一行为？
- 哪个问题是规则问题，哪个只是表现或输入映射问题？
- 达到什么阈值后保留、调整或删除功能？谁做最终决定？

### 主持脚本

#### 开场（照读）

“我们正在测试这个版本，不是在测试你。过程中请尽量说出你正在注意什么和准备做什么。遇到困难也没有关系，我可能不会立刻回答操作方法。你可以随时停止。”

需补充的同意说明：`[是否记录屏幕/音频、保存多久、如何退出；无记录则说明只做匿名笔记]`

#### 背景问题（最多三项）

1. `[与目标玩家判断直接相关的问题]`
2. `[常用设备或相似游戏经验]`
3. `[可选]`

#### 试玩任务

| 任务 | 给玩家的目标（不提示操作）           | 最长时间    | 观察项                   | 成功定义   |
| ---- | ------------------------------------ | ----------- | ------------------------ | ---------- |
| `T1` | `[例如：请开始并让局面发生一次变化]` | `[秒/分钟]` | `[首次动作、犹豫、误触]` | `[待填写]` |
| `T2` | `[例如：请结束当前局并重新开始]`     | `[待填写]`  | `[是否理解结果与重启]`   | `[待填写]` |

#### 主持人可用提示层级

0. 不提示，只提醒可以说出想法。
1. 重述目标，不指出界面或动作。
2. 指出可交互区域，不说明正确动作。
3. 明确操作并标记为“任务未独立完成”。

#### 结束问题

1. “你认为这一局的目标是什么？”
2. “哪一步最需要思考？为什么？”
3. “有哪个结果出乎你的预期？”
4. “如果再来一局，你会改变什么做法？”
5. `[与主要假设直接相关、避免诱导的问题]`

## 完成判定标准

- [ ] 主要假设可证伪，并在试玩前写好通过、失败和灰区阈值。
- [ ] 参与者标准、样本限制、版本、配置、种子和设备均可追溯。
- [ ] 统一主持脚本不会提示正确操作，并定义了提示级别。
- [ ] 每个任务都有最长时间、观察项和成功定义。
- [ ] 试玩版本已通过完整自动检查，技术故障有排除规则。
- [ ] 只收集最少匿名信息；额外记录已取得同意并有删除计划。
- [ ] 汇总把事实、原话和解释分开，结论没有超出样本证据。
- [ ] 结果明确导向保留、调整、移除、补测或停止中的一个决定。
- [ ] 后续变更会先进入 `TASK.md`，不会在复盘时直接扩大当前任务。
